# LedgerLock — Failure Log & Retrospective

| Date | What broke | Why | How I fixed it | What I'd do differently |
|---|---|---|---|---|
| 2026-08-23 | CrewAI / PyTorch Python 3.14 wheel unavailability | Default system python is 3.14 which lacks pre-built wheels for compiled ML libraries on Windows | Pinned virtual environment to Python 3.12 via `uv venv --python 3.12` | Always check runtime wheel readiness for heavy agent/ML stacks before environment initialization |
| 2026-08-23 | `uv pip install -e .` failed with `OSError: Readme file does not exist: README.md` | Hatchling backend validates the `readme` field in `pyproject.toml` during editable installation before `README.md` was created | Created `README.md` containing architecture and run instructions before re-triggering install | Create all package metadata files (`README.md`, `LICENSE`, etc.) before installing package in editable mode |
| 2026-08-23 | ChromaDB semantic search over-generalized TDS sections | Generic prompt `Section X statutory rate` in semantic vector query without metadata filter returned top chunk (194-O, 1%) for all sections | Added explicit ChromaDB metadata filter `where={"section": sec_clean}` and exact chunk matching with fallback statutory dictionary | Always combine semantic search with structured metadata filtering when querying discrete tax/regulatory codes |
| 2026-08-23 | Multi-line statutory rate regex in RAG chunker missed indented sub-bullets | `rag/build_index.py` regex expected `Statutory Rate: X%` on the same line, failing to capture nested sub-bullets (e.g. 194H 5%, 194C 2%, 194J 10%) | Updated regex parser to handle multi-line rate bullet declarations and explicit per-section statutory rate mappings | Always test chunk metadata parser with isolated unit tests before embedding into ChromaDB |
| 2026-08-23 | ChromaDB `upsert` with new IDs retained stale document chunks | When changing chunk ID scheme from `tds_sec_0` to `tds_sec`, `upsert` added new IDs without deleting stale IDs, causing `collection.get(where=...)` to return the first matching stale record with 0.01 rate | Added `client.delete_collection("tds_rules")` before recreating index to guarantee clean idempotency | Explicitly delete or recreate persistent vector collections when updating schema/ID formats |
| 2026-08-23 | OpenTelemetry `InMemorySpanExporter` module path mismatch | `InMemorySpanExporter` is located in `opentelemetry.sdk.trace.export.in_memory_span_exporter` rather than root `export` namespace in recent OTEL versions | Adjusted import to `from opentelemetry.sdk.trace.export.in_memory_span_exporter import InMemorySpanExporter` with fallback memory exporter | Verify exporter module sub-paths across minor OpenTelemetry SDK releases |
| 2026-08-23 | Tier 2 fuzzy matcher matched 2-way pairs without bank credit confirmation | Fuzzy matcher allowed matches between ledger and settlement when `b_match_id` was `None`, causing genuine missing bank records to be falsely matched | Enforced strict 3-way correspondence check requiring a valid bank credit for match confirmation; unconfirmed items route to exception explainer | In 3-way financial reconciliation, enforce 3-source integrity before committing any match to prevent false positives |
| 2026-08-23 | Truncated prefix slicing in split settlement candidate search | Slicing reference string to first 10 chars (`l_clean[:10]`) matched common batch date prefix (`payin20260`), causing all settlement rows to be aggregated into sum | Changed condition to exact substring matching `l_clean in clean_ref_str(s_ref)` so only true child part references are collected | Avoid arbitrary string slice lengths when comparing structured reference identifiers |
